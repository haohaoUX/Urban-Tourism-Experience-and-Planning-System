# 南昌旅游自定义路线地图工具 需求规格说明书（SRS）

> 文档状态：待审查
> 编写依据：《南昌旅游路线规划工具-功能需求文档》
> 编号规则：FR 为功能需求，NFR 为非功能需求，供测试用例追溯

---

# 1 引言

## 1.1 编写目的
本说明书对南昌旅游自定义路线地图工具的功能、性能、运行环境、数据和验收标准作出完整规定，作为系统设计、编码、测试和验收的统一依据。读者对象为项目开发成员、课程指导教师及评审人员。

## 1.2 项目背景
通用地图软件信息庞杂，旅游点位与无关地点混杂，且缺乏围绕游览路线规划的专门组织；现有旅游规划工具或功能臃肿、学习成本高，或只能按固定模板生成路线，用户自主权不足。

本项目面向来南昌旅游的游客及本地休闲用户，提供一款浏览器访问的轻量化路线规划工具，核心流程为「地图浏览选点 → 一键生成路线 → 路线管理」。

## 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 点位 | 地图上一个可浏览的地点，分景点、正餐美食、休闲市集小店、配套服务 4 类 |
| 待选点位清单 | 用户从地图挑选、用于生成路线的点位集合，是生成路线的前置数据 |
| 标记模式 | 地图只显示已加入待选清单点位的浏览模式 |
| 顺路最优模式 | 系统按点位间距离自动计算较短游览顺序的生成模式 |
| 清单顺序模式 | 严格按用户在待选清单中排列顺序生成路线的模式 |
| 液态玻璃 | 以背景模糊、半透明、细描边为特征的界面材质风格 |

# 2 任务概述

## 2.1 项目目标
在一个学期内交付可运行的 Web 端路线规划工具，实现南昌点位的浏览筛选、自主选点、双模式路线生成与路线管理，界面简约流畅，免安装、免登录即可使用。

## 2.2 用户特征

| 用户 | 特征 | 核心诉求 |
|------|------|----------|
| 外地游客 | 对南昌不熟悉，单次或短途出行 | 快速找到景点美食、获得顺路不绕路的路线 |
| 本地休闲用户 | 熟悉城市，多次使用 | 区分已去过点位、灵活安排行程 |
| 课程评审人员 | 关注工程完整性与可运行性 | 系统稳定、文档齐全、可按说明部署 |

## 2.3 运行环境

**客户端**
- 硬件：普通个人电脑，支持现代浏览器的设备
- 操作系统：Windows / macOS 等主流桌面系统
- 浏览器：Edge、Chrome、Safari、Firefox 近两年版本，需启用 JavaScript
- 网络：首次加载及地图 API 调用需联网；本地数据功能离线可用

**服务端**
- 常规 Web 应用服务器运行环境，提供 REST 接口与数据库连接
- 数据库：主流关系型数据库

## 2.4 条件与限制
- 本期不做注册登录、社区、在线支付与实时数据；
- 地图能力依赖第三方地图服务商 API，受其接口规则与配额约束；
- 路线顺路最优为近似算法，不保证数学上的全局最优。

# 3 功能需求

## 3.1 点位分类

**FR-01 点位分类展示**
系统将点位分为 4 类并以不同颜色 Marker 区分：景点（蓝）、正餐美食（橙）、休闲市集小店（绿）、配套服务（灰）。配套服务点位仅可浏览，不提供添加到路线入口，其余 3 类可参与路线生成。

## 3.2 主地图

**FR-02 地图浏览**
系统以南昌市全域为范围展示地图，主地图仅用于点位浏览，不渲染任何已生成路线；支持常规拖拽、缩放操作。

**FR-03 双维度筛选**
地图提供行政区（东湖区、西湖区、红谷滩区、青云谱区、青山湖区、新建区）和点位类型两组复选筛选，两层条件交集生效，默认全部勾选；条件变更后地图点位实时更新。

**FR-04 筛选面板交互**
筛选条件默认收起为「筛选」按钮，点击展开面板、再次点击收起，已选条件在收起后持续生效。

**FR-05 标记模式**
点击「标记」按钮切换标记模式，开启后地图仅显示待选清单内点位，关闭后恢复完整显示。

**FR-06 点位搜索**
顶部搜索框支持按点位名称关键词搜索，回车后定位到匹配点位、高亮 Marker 并弹出详情；无匹配或点位被筛选隐藏时给出明确提示。

**FR-07 悬停预览**
鼠标悬停 Marker 时显示含点位名称与分类的极简标签，移开后消失。

**FR-08 行政区边界高亮**
选中行政区时对应边界高亮显示，取消选中或全选时不显示边界。

**FR-09 视角复位**
点击复位按钮，地图回到南昌市全域默认视角，不改变筛选与选点状态。

**FR-10 筛选条件记忆**
刷新页面或切换页面后，用户上次设置的筛选条件保持生效，数据存于浏览器本地。

## 3.3 点位详情

**FR-11 详情气泡内容**
点击 Marker 弹出详情，统一展示点位名称、分类与行政区；可规划点位展示简介、开放时间、推荐停留时长，配套点位展示简介且无停留时长。

**FR-12 消费与门票信息**
正餐点位展示人均参考，收费景点展示门票参考，免费点位与配套点不显示该字段；信息为静态参考，不做购票跳转。

**FR-13 添加到路线**
可规划点位详情提供「添加到路线」按钮，点击后点位进入待选清单；同一点位不可重复添加，已添加时按钮置灰显示「已添加」，移除后恢复可点击。

**FR-14 周边点位查看**
详情提供「查看周边」，展示当前点位一定范围内的其他点位并可切换类型，点击列表项可跳转对应点位详情。

**FR-15 自定义备注**
用户可给点位添加不超过 50 字的备注，备注在待选清单与最终行程中可见。

## 3.4 待选点位清单

**FR-16 清单展示与统计**
清单实时显示已选点位数量，每个条目显示点位名称、分类标签与删除按钮。

**FR-17 数量提醒**
清单不设上限；点位达到 15 个时首次弹出友好提醒，之后每新增 5 个提醒一次，提醒不阻止继续添加。

**FR-18 移除与清空**
支持单个点位移除；提供一键清空按钮，清空后所有相关状态同步恢复。

**FR-19 点击定位**
点击清单条目，地图自动居中定位并高亮对应点位。

**FR-20 拖拽排序**
清单内点位支持鼠标拖拽调整顺序，排序结果实时保存并用于路线生成。

**FR-21 清单类型过滤**
清单提供全部/景点/美食/休闲快捷过滤，仅改变清单显示，不影响实际已选数据。

**FR-22 分组标签**
支持给点位打自定义分组标签，可按标签筛选与批量操作，标签不影响路线生成逻辑。

## 3.5 路线生成与管理

**FR-23 生成模式选择**
生成路线前可选择顺路最优（系统按距离自动排序）或清单顺序（按用户排列顺序）两种模式。

**FR-24 一键生成**
点击生成按钮基于当前待选清单生成路线；清单为空时提示先添加点位；生成成功仅弹出成功提示，不自动跳转页面。

**FR-25 路线列表与折叠卡片**
路线以卡片形式存放，折叠态显示路线名称与点位数量，点击展开详情。

**FR-26 路线命名与删除**
路线支持自定义命名，默认按生成顺序命名为路线 1、路线 2……；支持单条删除。

**FR-27 路线详情**
展开后展示独立小地图（仅含本路线点位与顺序连线、无筛选）和文字行程清单，行程包含点位顺序、停留时长与用户备注。

**FR-28 顺序微调**
已生成路线支持在详情内拖拽调整点位顺序，小地图连线与总时长同步更新，无需重新生成。

**FR-29 时长估算**
系统按点位停留时长与点位间通勤时长估算总时长，通勤支持驾车/步行切换，结果以小时和分钟展示。

**FR-30 路线复制与文本导出**
支持一键复制路线副本用于方案对比；支持将行程整理为纯文本复制到剪贴板。

## 3.6 辅助功能

**FR-31 点位收藏**
独立于待选清单的收藏功能，可长期保存点位并批量加入待选清单，两者数据独立。

**FR-32 已打卡标记**
可标记点位为已去过，标记后 Marker 半透明显示，可选择隐藏已打卡点位，不影响路线生成。

# 4 非功能需求

## 4.1 性能需求（NFR-PERF）
- NFR-PERF-01：常规点击、筛选、展开等操作响应无明显延迟，界面过渡保持流畅；
- NFR-PERF-02：20 个点位以内，顺路最优算法在前端或后端即时返回结果；
- NFR-PERF-03：同屏玻璃面板控制在 5 个以内，禁止模糊嵌套，地图拖拽期间允许临时降低模糊强度；
- NFR-PERF-04：动画只使用 transform、opacity 属性，避免页面重排。

## 4.2 安全需求（NFR-SEC）
- NFR-SEC-01：用户输入内容（备注、搜索词）做长度限制与输出转义，防止脚本注入；
- NFR-SEC-02：本地存储仅保存筛选、清单、备注等非敏感数据；
- NFR-SEC-03：地图 API Key 不在前端明文暴露完整权限，通过后端代理或受限 Key 方式使用。

## 4.3 兼容性需求（NFR-COMPAT）
- NFR-COMPAT-01：支持 Edge、Chrome、Safari、Firefox 近两年版本；
- NFR-COMPAT-02：玻璃效果在不支持的浏览器自动降级为半透明纯色，功能不受影响；
- NFR-COMPAT-03：响应式覆盖宽屏、900px 及 640px 以下断点，窄屏侧边栏改为抽屉式。

## 4.4 易用性需求（NFR-USE）
- NFR-USE-01：免安装、免注册登录，核心操作不超过 3 步；
- NFR-USE-02：提供空状态提示与操作反馈，所有可点击元素均有真实响应；
- NFR-USE-03：响应系统减少动效设置，自动关闭非必要动画；
- NFR-USE-04：支持浅色/深色模式切换。

## 4.5 可维护性需求（NFR-MAINT）
- NFR-MAINT-01：颜色、圆角、阴影、动效统一为设计变量，模块职责清晰；
- NFR-MAINT-02：前后端分离、接口约定明确，便于后续功能扩展。

# 5 数据需求

## 5.1 点位数据
每个点位包含：编号、名称、类型、所属行政区、经纬度坐标、简介、开放时间、推荐停留时长（配套点无）、门票或人均参考（可选）、用户备注（可选）、打卡状态。

## 5.2 路线数据
每条路线包含：路线编号、名称、生成模式、按序排列的点位序列、创建时间。

## 5.3 本地存储数据
浏览器本地保存：筛选条件、待选清单、点位备注、收藏与打卡记录；数据不包含敏感信息，清除浏览器数据后恢复初始状态。

# 6 验收标准

## 6.1 功能验收
- 第 3 章每条 FR 均可被测试用例验证，主流程（选点 → 生成 → 查看管理）可完整走通；
- 配套点位不能被加入路线，重复添加、空清单生成等异常情况有正确拦截与提示。

## 6.2 非功能验收
- 在规定浏览器范围内界面正常、操作流畅，降级环境下功能可用；
- 无未处理的脚本注入风险，响应式断点下无内容错位。

## 6.3 交付验收
- 交付可运行的前后端工程、数据库脚本与初始数据；
- 交付可行性报告、开发计划、本 SRS、设计文档、测试文档、README 及答辩材料。
