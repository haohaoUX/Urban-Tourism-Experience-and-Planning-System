# 迭代任务清单（Issue 起草稿）

> 用途：正式开发前先在 GitHub Issues 中创建对应 Issue，再按 `feature/<issue号>-<简述>` 开分支开发，禁止没有 Issue 的代码变更。
> 规则：每条 Issue 必须包含「背景 / 需求描述 / 任务清单 / 验收标准 / 关联 / 元信息」六段，验收标准必须可验证（"能……"而非"做好……"）。
> 分工：刘昊（架构 / 评审 / 发布）、刘克（前端）、肖睿（后端）、张仕琪（测试 / 文档）。
> 里程碑：`v0.2.0`（第 12 周 Beta）、`v1.0.0`（第 16 周终版）。

## v0.2.0 迭代（Beta）

### 1. 接入高德地图 JS API 替换模拟底图
- 负责人：刘克 ｜ 标签：`frontend` `feature` `P0` ｜ 预估：8h
- 验收标准：
  - [ ] 地图页可加载高德真实底图，能拖拽、滚轮缩放、双击放大
  - [ ] 16 个点位按经纬度落到真实坐标，标记样式与模拟版一致
  - [ ] 提供「复位到南昌市中心」按钮，点击后视图恢复默认层级
  - [ ] Key 不硬编码在前端源码，缺失时页面给出明确提示且不白屏

### 2. 点位备注与拖拽排序
- 负责人：刘克 ｜ 标签：`frontend` `feature` `P1` ｜ 预估：6h
- 验收标准：
  - [ ] 待选清单内可拖拽调整顺序，松手后顺序持久化
  - [ ] 每个点位可填写不超过 50 字的备注，刷新页面后备注不丢失
  - [ ] 备注随路线保存，重新打开路线详情能正确回显

### 3. 收藏与打卡（我的标记）
- 负责人：刘克 ｜ 标签：`frontend` `feature` `P1` ｜ 预估：5h
- 验收标准：
  - [ ] 点位详情提供「收藏」「打卡」按钮，状态即时反馈
  - [ ] 「标记」筛选可只显示已收藏或已打卡点位
  - [ ] 数据经 `favorite` / `visited` 接口持久化，刷新后不丢失

### 4. 前端空态、错误态与加载态统一
- 负责人：刘克 ｜ 标签：`frontend` `refactor` `P1` ｜ 预估：4h
- 验收标准：
  - [ ] 列表为空、搜索无结果、接口 5xx、请求超时四类场景均有明确文案
  - [ ] 所有请求失败时不出现白屏，可重试
  - [ ] 生成路线时按钮进入 loading 且防重复点击

### 5. 点位数据扩充至 30 个并补全字段
- 负责人：肖睿 ｜ 标签：`backend` `data` `P0` ｜ 预估：6h
- 验收标准：
  - [ ] `init_data.py` 可重复执行，写入 30 个点位且不产生重复主键
  - [ ] 每个点位包含名称、类型、行政区、经纬度、简介、停留时长
  - [ ] 4 类点位均有数据，`facility` 类型不少于 4 个

### 6. 路线详情接口支持备注字段
- 负责人：肖睿 ｜ 标签：`backend` `feature` `P1` ｜ 预估：4h
- 验收标准：
  - [ ] `PUT /api/routes/{id}/items` 能保存并回传 `user_note`
  - [ ] 备注超过 50 字时返回 422 而非 500
  - [ ] 补充对应的 pytest 用例

### 7. 后端统一异常响应与错误码文档
- 负责人：肖睿 ｜ 标签：`backend` `refactor` `P1` ｜ 预估：4h
- 验收标准：
  - [ ] 未捕获异常统一返回 `{code, message, data}` 结构
  - [ ] 400/404/409/422 各场景在 `docs/design/04-API接口设计.md` 有对应说明
  - [ ] 参数非法时响应体不含堆栈信息

### 8. 后端单元测试补齐（算法 + 接口）
- 负责人：肖睿 ｜ 标签：`backend` `test` `P0` ｜ 预估：6h

  - [ ] 接口测试覆盖点位列表筛选、路线生成、路线删除的正常与异常分支
  - [ ] 无 `expect(true)` 式空断言

### 9. 测试用例表与缺陷记录
- 负责人：张仕琪 ｜ 标签：`test` `docs` `P0` ｜ 预估：6h
