# 南昌旅游自定义路线地图工具 可行性研究报告

> 文档状态：待审查
> 编写依据：《南昌旅游路线规划工具 - 功能需求文档》
> 报告目的：从技术、经济、操作三个维度论证项目是否值得立项、能否在课程周期内完成



***

## 一、项目背景

随着城市短途旅游和自助游的普及，游客在规划行程时普遍面临两个问题：



1. 通用地图软件信息庞杂，旅游点位与无关地点混杂，缺乏围绕「游览路线规划」的专门组织方式；

2. 同类旅游规划工具要么功能臃肿、学习成本高，要么只能按固定模板生成路线，用户缺乏自主权。

本项目面向来南昌旅游的游客及本地休闲用户，做一款聚焦南昌城市点位的轻量化自定义路线规划工具。用户在地图上自主挑选景点、正餐美食、休闲市集小店等点位，通过一键生成获得可管理的游览路线，配套服务点位仅作地图参考不参与路线。



***

## 二、技术可行性

### 1. 总体技术形态

系统采用成熟的 **Web 前后端分离架构**，用户通过浏览器访问，无需安装客户端。



| 层次   | 技术方向                       | 可行性说明                           |
| ---- | -------------------------- | ------------------------------- |
| 前端   | 主流前端框架 + 地图 JavaScript API | 技术资料丰富，团队已具备 Web 开发基础           |
| 后端   | 常规 Web 服务框架，提供 REST 接口     | 仅需处理点位、路线的增删改查，业务逻辑不复杂          |
| 数据存储 | 关系型数据库保存点位与路线数据            | 数据结构清晰，表关系简单                    |
| 地图能力 | 通用地图服务商开放 API              | 底图、行政区边界、路径规划、搜索均有现成接口，无需自研地理引擎 |

### 2. 关键功能的技术支撑



* **点位筛选与搜索**：基于数据库条件查询 + 地图 API 地理编码，属常规开发内容。

* **双模式路线生成**：


  * 清单顺序模式无算法难度，直接按用户排序输出；

  * 顺路最优模式采用轻量 TSP（旅行商问题）近似算法，在本项目点位规模（通常 20 个以内）下，最近邻等启发式算法即可在前端或后端快速算出结果，无需高性能计算资源。

* **时长估算与连线**：通勤时长直接调用地图 API 路径规划接口获取，路线连线由地图 API 折线组件绘制。

* **本地记忆与无登录使用**：用户筛选条件、临时清单可通过浏览器 localStorage 保存，不强制账号系统。

* **液态玻璃视觉风格**：基于标准 CSS（backdrop-filter、CSS 变量、过渡动画）实现，现代浏览器均支持，并准备了不支持时的纯色降级方案。

### 3. 技术风险与对策



| 风险点              | 对策                                    |
| ---------------- | ------------------------------------- |
| 地图 API 免费额度或调用限制 | 开发期使用免费额度，点位通勤数据可缓存，避免重复调用            |
| 玻璃模糊效果在低端设备性能下降  | 控制同屏玻璃面板数量，禁止模糊嵌套，提供降级样式              |
| 路线算法在点位极多时变慢     | 不设硬性上限但设置数量提醒，课程场景下数据量小，近似算法完全够用      |
| 浏览器兼容性差异         | 用 @supports 做特性检测，核心功能不依赖特效，降级后仍可正常使用 |

**结论：项目所涉及的全部技术均为成熟、通用的 Web 技术，无未攻克的技术难点，在课程周期内技术上可行。**

## 三、经济可行性

### 1. 开发成本



* 开发工具（编辑器、浏览器、数据库）均有免费开源版本，无需购买软件许可；

* 前后端框架、地图 SDK 均为免费开放使用；

* 项目规模小，普通个人电脑即可完成全部开发与测试，无需额外硬件投入。

### 2. 运行成本



* 课程阶段可在本地或免费云环境部署演示，无服务器租赁成本；

* 地图 API 调用量在课程演示范围内，免费额度足以覆盖；

* 系统不涉及支付、票务、实时数据采购等需要持续付费的第三方服务。

### 3. 人力成本



* 功能范围经过刻意控制，只围绕「选点 → 生成路线」核心流程，不做社区、电商、实时人流等重投入模块，小团队在一个学期内可以完成。

**结论：项目几乎零资金投入，运行成本低，人力投入与课程周期匹配，经济上可行。**



***

## 四、操作可行性

### 1. 用户使用门槛



* 浏览器直接打开即可使用，无需下载安装、无需注册登录；

* 核心操作只有「点击点位 → 添加到路线 → 一键生成」三步，符合普通用户的地图使用习惯；

* 界面采用简约玻璃风格，信息层级清晰，配套点位与可规划点位视觉区分明确。

### 2. 维护与管理



* 点位数据为结构化静态数据，后续新增、修改点位只需维护数据库记录；

* 系统模块划分清晰，前后端职责分离，便于后续维护和功能扩展。

### 3. 适配性



* 响应式布局，桌面与窄屏均可正常浏览操作；

* 支持浅色 / 深色模式，兼顾不同使用环境。

**结论：用户操作简单、维护成本低，操作上可行。**



***

## 五、可行性结论

综合技术、经济、操作三方面分析：



1. 技术上全部基于成熟 Web 技术与通用地图 API，无技术盲区，风险均有对应对策；

2. 经济上零资金门槛、低运行成本；

3. 操作上免安装、低学习成本、易维护。

**本项目立项条件成立，建议按计划进入开发阶段。**
