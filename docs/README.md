## 阅读顺序建议

1. 新人加入：`README.md` → `docs/design/02-总体架构设计.md` → `CONTRIBUTING.md`
2. 接手某个功能：`docs/requirements/02-功能需求文档.md` → `docs/design/05-详细设计.md` → 对应 `docs/adr/`
3. 改动接口：`docs/design/04-API接口设计.md` → 前后端同步修改 → 更新本表指向的文档

## 维护约定

- 文档与代码同时变更的，放在**同一个 PR** 中提交。
- 设计决策发生反转时，新增一条 ADR 说明原因，不要直接改写旧 ADR。
- 文档中的图使用 Mermaid 或已入库的图片，不引用仅存在于 PPT 中的截图。
