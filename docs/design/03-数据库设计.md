## 一、实体关系总览

### 1. 核心实体



| 实体            | 说明                    |
| ------------- | --------------------- |
| 点位 POI        | 地图上一个地点，含分类、坐标、开放信息等  |
| 路线 Route      | 一次生成的游览路线，含名称与生成模式    |
| 行程项 RouteItem | 路线与点位的关联，记录游览顺序与备注    |
| 标签 Tag        | 用户给点位打的分组标签（第一天、上午场等） |
| 收藏 Favorite   | 点位收藏（扩展，本期可走本地）       |
| 打卡 Visited    | 已去过标记（扩展，本期可走本地）      |

### 2. 关系说明



* 一条路线 1 — N 个行程项；一个行程项对应 1 个点位；

* 点位 N — N 标签（通过关联表）；

* 点位 1 — N 收藏 / 打卡记录；

* 同一点位可被不同路线引用，因此路线与点位是通过行程表解耦的多对多关系。

### 3. ER 简图（ASCII）



```
                         ┌──────────┐
                         │   tag    │
                         └────┬─────┘
                              │ N
                         ┌────┴─────┐
┌──────────┐  1      N    │  poi_tag │
│  route   │──────────────┴────┬─────┘
└────┬─────┘                   │ N
     │ 1                       │
     │ N                  ┌────┴─────┐
┌────┴─────┐ N         1  │   poi    │
│route_item│──────────────►└──┬───┬───┘
└──────────┘                  │   │
                     ┌────────┘   └────────┐
                     │ N                  │ N
                ┌────┴─────┐         ┌────┴─────┐
                │ favorite │         │ visited  │
                └──────────┘         └──────────┘
```

## 二、表结构设计

### 1. poi 点位表



| 字段            | 类型            | 约束    | 说明                            |
| ------------- | ------------- | ----- | ----------------------------- |
| poi\_id       | BIGINT        | PK，自增 | 点位编号                          |
| name          | VARCHAR(100)  | 非空    | 点位名称                          |
| type          | VARCHAR(20)   | 非空    | 类型：spot/food/leisure/facility |
| district      | VARCHAR(20)   | 非空    | 所属行政区                         |
| address       | VARCHAR(200)  | 可空    | 详细地址                          |
| longitude     | DECIMAL(10,6) | 非空    | 经度（GCJ-02）                    |
| latitude      | DECIMAL(10,6) | 非空    | 纬度（GCJ-02）                    |
| description   | TEXT          | 可空    | 点位简介                          |
| open\_time    | VARCHAR(100)  | 可空    | 开放时间描述                        |
| stay\_minutes | INT           | 可空    | 推荐停留时长（分钟），配套点为 NULL          |
| ticket        | VARCHAR(50)   | 可空    | 门票参考                          |
| cost          | VARCHAR(50)   | 可空    | 人均消费参考                        |
| status        | TINYINT       | 默认 1  | 1 正常 0 停用                     |
| created\_at   | DATETIME      | 自动    | 创建时间                          |
| updated\_at   | DATETIME      | 自动    | 更新时间                          |

索引：`idx_type(type)`、`idx_district(district)`、`idx_type_district(type, district)` 用于筛选查询。

### 2. route 路线表



| 字段             | 类型           | 约束    | 说明                      |
| -------------- | ------------ | ----- | ----------------------- |
| route\_id      | BIGINT       | PK，自增 | 路线编号                    |
| name           | VARCHAR(100) | 非空    | 路线名称（默认路线 1…，可改）        |
| gen\_mode      | VARCHAR(20)  | 非空    | smart 顺路最优 /manual 清单顺序 |
| total\_minutes | INT          | 可空    | 估算总时长（分钟）               |
| created\_at    | DATETIME     | 自动    | 创建时间                    |
| updated\_at    | DATETIME     | 自动    | 更新时间                    |

### 3. route\_item 行程项表



| 字段         | 类型          | 约束       | 说明           |
| ---------- | ----------- | -------- | ------------ |
| item\_id   | BIGINT      | PK，自增    | 行程项编号        |
| route\_id  | BIGINT      | FK→route | 所属路线         |
| poi\_id    | BIGINT      | FK→poi   | 关联点位         |
| seq        | INT         | 非空       | 游览顺序（从 1 开始） |
| user\_note | VARCHAR(50) | 可空       | 该点位私人备注      |

约束：`UNIQUE(route_id, poi_id)` 防同路线重复点位；`UNIQUE(route_id, seq)` 保证顺序唯一；索引 `idx_route_seq(route_id, seq)`。

### 4. tag 标签表



| 字段      | 类型          | 约束    | 说明   |
| ------- | ----------- | ----- | ---- |
| tag\_id | BIGINT      | PK    | 标签编号 |
| name    | VARCHAR(50) | 非空，唯一 | 标签名  |

### 5. poi\_tag 点位标签关联表



| 字段      | 类型                 | 约束     |
| ------- | ------------------ | ------ |
| poi\_id | BIGINT             | FK→poi |
| tag\_id | BIGINT             | FK→tag |
| 主键      | (poi\_id, tag\_id) | 联合主键   |

### 6. favorite 收藏表（扩展）



| 字段           | 类型       | 约束     |
| ------------ | -------- | ------ |
| favorite\_id | BIGINT   | PK     |
| poi\_id      | BIGINT   | FK→poi |
| created\_at  | DATETIME | 自动     |

### 7. visited 打卡表（扩展）



| 字段          | 类型       | 约束        |
| ----------- | -------- | --------- |
| visited\_id | BIGINT   | PK        |
| poi\_id     | BIGINT   | FK→poi，唯一 |
| marked\_at  | DATETIME | 自动        |

> 说明：本期无登录、单用户，收藏、打卡、临时备注也可只存浏览器 localStorage；以上扩展表用于后续登录与多端同步，工程上先预留结构，不增加本期开发负担。

## 三、建表脚本（MySQL DDL）



```
-- 建库
CREATE DATABASE IF NOT EXISTS nanchang_trip
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE nanchang_trip;

-- 点位表
CREATE TABLE poi (
  poi_id       BIGINT AUTO_INCREMENT PRIMARY KEY,
  name         VARCHAR(100) NOT NULL,
  type         VARCHAR(20)  NOT NULL,
  district     VARCHAR(20)  NOT NULL,
  address      VARCHAR(200),
  longitude    DECIMAL(10,6) NOT NULL,
  latitude     DECIMAL(10,6) NOT NULL,
  description  TEXT,
  open_time    VARCHAR(100),
  stay_minutes INT,
  ticket       VARCHAR(50),
  cost         VARCHAR(50),
  status       TINYINT DEFAULT 1,
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_type (type),
  INDEX idx_district (district),
  INDEX idx_type_district (type, district)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 路线表
CREATE TABLE route (
  route_id      BIGINT AUTO_INCREMENT PRIMARY KEY,
  name          VARCHAR(100) NOT NULL,
  gen_mode      VARCHAR(20)  NOT NULL,
  total_minutes INT,
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 行程项表
CREATE TABLE route_item (
  item_id   BIGINT AUTO_INCREMENT PRIMARY KEY,
  route_id  BIGINT NOT NULL,
  poi_id    BIGINT NOT NULL,
  seq       INT NOT NULL,
  user_note VARCHAR(50),
  CONSTRAINT fk_ri_route FOREIGN KEY (route_id) REFERENCES route(route_id) ON DELETE CASCADE,
  CONSTRAINT fk_ri_poi   FOREIGN KEY (poi_id)   REFERENCES poi(poi_id),
  UNIQUE KEY uq_route_poi (route_id, poi_id),
  UNIQUE KEY uq_route_seq (route_id, seq),
  INDEX idx_route_seq (route_id, seq)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 标签表
CREATE TABLE tag (
  tag_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  name   VARCHAR(50) NOT NULL UNIQUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 点位标签关联表
CREATE TABLE poi_tag (
  poi_id BIGINT NOT NULL,
  tag_id BIGINT NOT NULL,
  PRIMARY KEY (poi_id, tag_id),
  CONSTRAINT fk_pt_poi FOREIGN KEY (poi_id) REFERENCES poi(poi_id) ON DELETE CASCADE,
  CONSTRAINT fk_pt_tag FOREIGN KEY (tag_id) REFERENCES tag(tag_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 收藏表（扩展）
CREATE TABLE favorite (
  favorite_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  poi_id      BIGINT NOT NULL,
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_fav_poi FOREIGN KEY (poi_id) REFERENCES poi(poi_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 打卡表（扩展）
CREATE TABLE visited (
  visited_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  poi_id     BIGINT NOT NULL UNIQUE,
  marked_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_vis_poi FOREIGN KEY (poi_id) REFERENCES poi(poi_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 四、数据扩充计划



| 阶段   | 目标量      | 数据来源                                        |
| ---- | -------- | ------------------------------------------- |
| 结构跑通 | 16 个     | 手动整理的核心点位，验证表结构与接口                          |
| 中期演示 | 30-40 个  | 手动补充核心景点 / 市集，保证信息质量                        |
| 完整版本 | 60-100 个 | 高德 POI 搜索 API 按行政区 + 类型批量检索，脚本清洗后入库，人工补关键字段 |

### 批量导入方式



1. 后端脚本调用高德 POI 搜索 Web 接口，按区 + 类型分页拉取名称、坐标、地址；

2. 经坐标去重、字段映射后写入 poi 表；

3. 简介、开放时间、停留时长等手工字段后续在管理界面或脚本中补全；

4. 导入前按经纬度和名称做去重，避免重复点位。

## 五、设计说明与后期可调整点



* 点位经纬度统一使用高德坐标系（GCJ-02），避免叠加偏移；

* 路线删除时行程项通过外键级联删除，点位本身不受影响；

* 后续若加用户系统，只需在 route/favorite/visited 上增加 user\_id 字段并加索引，表结构无需重构；

* 字段长度、枚举值和扩展表可在写完代码看实际效果后再增删调整。
