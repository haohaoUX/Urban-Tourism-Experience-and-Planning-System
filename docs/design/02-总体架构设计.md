# 南昌旅游自定义路线地图工具 总体架构设计

> 文档状态：待审查
> 技术基线：Vue 3 + Vite ／ FastAPI ／ MySQL 8.0 ／ 高德地图 API
> 架构模式：前后端分离的分层架构

---

## 一、架构设计原则

1. **前后端分离**：前端负责界面渲染与交互，后端负责业务逻辑与数据，通过 REST 接口通信；
2. **分层解耦**：各层只与相邻层交互，职责单一，便于独立开发和测试；
3. **轻量可落地**：不引入微服务、消息队列等重型组件，单体后端 + 单页前端即可支撑全部功能；
4. **Key 安全**：需要保护的地图能力通过后端代理，前端不暴露完整权限。

│  └──────────────┘  └──────────────┘  └───────────────────┘  │
│  ┌──────────────┐  ┌────────────────────────────────────┐   │

│  └──────────────┘  └────────────────────────────────────┘   │

### 2. 各层职责

| 层 | 技术 | 职责 |
|----|------|------|
| 表现层 | Vue 3 + 浏览器 | 界面渲染、用户交互、地图展示、本地数据存储 |
| 接口层 | FastAPI 路由 + Pydantic | 接收请求、参数校验、返回 JSON、统一异常处理 |
| 业务层 | FastAPI Services | 点位筛选搜索、路线生成算法、业务规则校验 |
| 数据访问层 | SQLAlchemy ORM | 数据库读写，隔离 SQL 细节 |
| 数据层 | MySQL | 持久化点位、路线、行程数据 |
| 外部服务 | 高德 API | 底图、路径规划、地理编码、边界与周边能力 |

### 3. 数据流向

- **浏览选点**：前端 → 后端点位接口 → ORM → MySQL → 返回点位 JSON → 前端用高德 JS API 绘制 Marker；
- **路线生成**：前端提交清单与模式 → 后端业务层算法排序（或前端算好提交）→ 路线持久化 → 返回结果；
- **通勤时长**：后端调用高德路径规划 Web 服务 → 取回时长 → 参与总时长估算；
- **本地数据**：筛选条件、临时清单直接存浏览器 localStorage，不经过后端。

|------|------|----------|

## 四、后端模块划分

| 模块 | 职责 |
|------|------|
| 点位模块 | 点位列表、条件筛选、详情、搜索接口 |
| 路线模块 | 路线生成、查询、重命名、顺序微调、删除、复制 |

| 数据模型模块 | SQLAlchemy ORM 模型与表关系 |
| 数据校验模块 | Pydantic 请求/响应模型 |
| 核心模块 | 配置管理、统一异常、日志、跨域处理 |

## 五、部署架构

```
浏览器  ──HTTP──►  Web 服务器（静态托管前端构建产物）
        ──API───►  Uvicorn/FastAPI 服务  ──► MySQL
                    │
                    └──► 高德 Web 服务 API
```

- 前端 `npm run build` 生成静态文件，由 Web 服务器托管；
- 后端作为独立服务运行，开发期通过 Vite 代理解决跨域，生产期通过同源部署或 CORS 配置；
- MySQL 独立存储数据，提供初始化脚本和点位初始数据。

## 七、架构可扩展性

- 后续若加登录，只需在接口层增加认证模块，现有业务不受影响；
- 点位和路线模块独立，新增点位类型或路线策略只需扩展对应服务；
- 设计 Token 与组件化结构支持快速换肤和深色模式扩展。
