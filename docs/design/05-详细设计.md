## 一、选点流程

### 1. 添加点位流程

```
用户点击 Marker
      │
      ▼
打开点位详情
      │
      ├─ 类型为 facility（配套点）？──是──► 不显示添加按钮，流程结束
      │否
      ▼
该点位已在待选清单？
      │
      ├─ 是 ──► 按钮置灰显示「已添加」，不可点击
      │否
      ▼
点击「添加到路线」
      │
      ▼
追加到待选清单（保持添加顺序）
      │
      ▼
检查数量 n：
  n = 15，或 n > 15 且 (n-15) 是 5 的倍数？
      │
      ├─ 是 ──► 弹出友好提醒（不阻止添加）
      │否
      ▼
更新按钮为「已添加」、刷新清单与数量统计
      │
      ▼
写入本地存储
```

**添加伪代码**
```
function addPoi(poiId):
    p = getPoi(poiId)
    if p.type == 'facility': return error('配套点位不能加入路线')
    if poiId in state.selected: return error('点位已添加')
    state.selected.append(poiId)
    n = state.selected.length
    if n == 15 or (n > 15 and (n - 15) % 5 == 0):
        showReminder('点位较多，可能影响单日游览体验')
    refreshSelectedList()
    saveLocal()
```

### 2. 移除与清空流程

```
单个移除：
点击删除按钮 ──► 从清单剔除 ──► 详情按钮恢复「添加到路线」
            └──► 同步刷新地图、清单、本地存储

一键清空：
点击清空 ──► 清单为空 ──► 所有点位按钮恢复可添加
        └──► 刷新统计与本地存储
```

### 3. 数量提醒规则
- 不设上限；触发点为 15、20、25、30……
- 仅提示，不阻断；条件表达式：`n === 15 || (n > 15 && (n - 15) % 5 === 0)`。

## 二、筛选与标记模式

### 1. Marker 显隐判定

```
function markerVisible(p):
    if state.markMode and p.id not in state.selected:
        return false
    if p.district not in state.districts:
        return false
    if p.type not in state.types:
        return false
    return true
```
任一条件变化即重新执行全部点位判定，实时更新显隐。

### 2. 标记模式
- 开启：只显示 `state.selected` 中的点位，其余隐藏；
- 关闭：恢复由筛选条件决定的完整显示。

### 3. 筛选条件记忆
筛选结果存 localStorage，页面加载时先读取再渲染，刷新后保持。

## 三、路线生成详细设计

### 1. 清单顺序模式（manual）

```
function manualOrder(poiIds):
    return copy(poiIds)   // 严格按用户清单顺序，不做任何调整
```

### 2. 顺路最优模式（smart）——最近邻算法

**算法步骤**
1. 以清单第一个点位为起点；
2. 从当前点位出发，在未访问点位中找距离最近的一个，作为下一站；
3. 重复直到所有点位访问完毕；
4. 输出顺序。

**伪代码**
```
function nearestNeighbor(poiIds):
    remaining = copy(poiIds)
    order = [remaining.shift()]
    while remaining.length > 0:
        current = getPoi(last(order))
        bestId = null
        bestDist = INFINITY
        for id in remaining:
            p = getPoi(id)
            d = distance(current, p)
            if d < bestDist:
                bestDist = d
                bestId = id
        order.append(bestId)
        remaining.remove(bestId)
    return order
```

**距离计算**
- 小范围可用经纬度平面距离近似；
- 推荐 Haversine 公式算真实球面距离（米）：
```
function haversine(a, b):
    R = 6371000
    dLat = rad(b.lat - a.lat)
    dLng = rad(b.lng - a.lng)
    h = sin(dLat/2)^2 + cos(rad(a.lat)) * cos(rad(b.lat)) * sin(dLng/2)^2
    return 2 * R * asin(sqrt(h))
```

**复杂度与边界**
- 时间复杂度 O(n²)，n=20 时约 400 次比较，前端即可瞬时完成；
- 0 个点位：拦截并提示；1 个点位：直接返回该点，不计算；
- 最近邻是近似解，不保证全局最优，符合 SRS 中 FR-23 的定义。


## 四、时长估算与顺序微调

### 1. 总时长估算

```
function estimateDuration(orderedIds, travelMode):
    stayTotal = sum(stay_minutes of each poi)
    commuteTotal = 0
    for i in 1 .. orderedIds.length - 1:
        d = getDuration(orderedIds[i-1], orderedIds[i], travelMode)
        commuteTotal += d
    return stayTotal + commuteTotal
```

**通勤时长获取优先级**
1. 调用高德路径规划接口，取真实 duration；
2. 接口失败或离线时，用直线距离兜底估算：
   - 驾车：距离 ÷ 30km/h（市区均速）
   - 步行：距离 ÷ 5km/h
- 切换 travel_mode 时重新计算，结果格式化为「X 小时 X 分钟」。

### 2. 顺序微调流程

```
在路线详情拖拽点位
      │
      ▼
前端按新顺序重排 items
      │
      ▼
提交 PUT /routes/{id}/items
      │
      ▼
后端重排 seq、重算 total_minutes
      │
      ▼
小地图连线与时长同步重绘（无需重新生成）
```

## 五、地图渲染流程

### 1. 主地图首次渲染
```
初始化地图（高德 JS API）
      │
      ▼
请求 GET /api/pois 获取点位
      │
      ▼
按 type 生成对应颜色 Marker（白描边圆形徽章）
      │
      ▼
绑定点击、悬停事件
      │
      ▼
应用当前筛选与标记模式显隐
```

### 2. 路线独立小地图渲染
```
取路线详情中的点位坐标
      │
      ▼
按 seq 绘制编号圆点（白描边）
      │
      ▼
用 polyline 按顺序连接（虚线样式）
      │
      ▼
顺序微调即重绘 polyline
```

### 3. 视角复位
调用地图 setCenter/setZoom 回到南昌全域默认视角，不改任何数据状态。

## 七、本地存储设计

**存储键**：`nanchang_trip_data`

**数据结构**
```json
{
  "selectedIds": [1, 6, 13],
  "districts": ["东湖区", "西湖区"],
  "types": ["spot", "food", "leisure", "facility"],
  "notes": { "1": "看日落最佳时间" },
  "favorites": [2, 5],
  "visited": [3],
  "genMode": "smart"
}
```

**读写规则**
- 状态变更即整体写入，页面加载时读取并合并默认值；
- 只存非敏感数据，清除浏览器数据后恢复初始状态；
- 后端数据库为最终持久化，本地存储负责体验与离线能力，两者分工不冲突。
