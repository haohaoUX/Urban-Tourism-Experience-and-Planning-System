## 二、前端选型：Vue 3 + Vite

### 1. 选择理由



* 模板语法与团队已有的小程序开发经验接近，学习和迁移成本最低；

* 组合式 API 适合把地图、筛选、清单等交互逻辑按功能组织，代码清晰；

* Vite 启动快、热更新即时，一人开发迭代效率高；

* 中文社区资料丰富，问题易检索。

### 2. 配套工具



* 路由：Vue Router（地图 / 规划两个视图切换）；

* 状态管理：轻量响应式状态即可，复杂时引入 Pinia；

* 拖拽排序：必要时使用 vuedraggable 等轻量库，不引入重型依赖。

### 3. 不引入重型 UI 组件库

Element Plus、Vant 等组件库自带固定视觉风格，与液态玻璃 iOS 风冲突，定制成本高于手写。决定**界面 CSS 全部手写**，直接复用《视觉风格规范》中的设计 Token（CSS 变量），仅在拖拽等个别场景引入轻量工具，保证风格统一。



***

## 三、后端选型：Python + FastAPI

### 1. 选择理由



* 团队 Python 基础最扎实，开发速度快，适合实际一人承担的情况；

* FastAPI 原生异步、性能好，自动生成 Swagger/OpenAPI 接口文档，可直接作为 API 文档基础，减少重复编写；

* 数据校验依赖 Pydantic，参数校验和错误处理规范；

* 路线生成算法（最近邻等近似算法）用 Python 实现简单直接。

### 2. 职责范围



* 提供点位查询、筛选、搜索、路线增删改查的 REST 接口；

* 代理地图 API 调用，避免前端暴露完整权限 Key；

* 承载顺路最优路线算法（也可按性能需要放在前端）。

### 3. 运行方式

开发期用 Uvicorn 本地启动，前后端通过 Vite 代理跨域；后期可配合 Gunicorn/Uvicorn 部署。



***

## 四、数据库选型：MySQL 8.0

### 1. 选择理由



* 关系型结构与点位、路线的清晰表关系高度匹配；

* 课程项目主流选型，ER 图、表结构文档规范，教师认可度高；

* 免费、社区资料多，与 FastAPI 对接成熟（SQLAlchemy + PyMySQL）。

### 2. 数据访问

使用 SQLAlchemy ORM 操作数据库，配合建表 SQL 脚本和点位初始数据，支持一键初始化。

### 3. 备用方案

本地快速演示或无 MySQL 环境时，可切换 SQLite，仅改连接配置，不影响业务代码。



***

## 五、地图服务选型：高德开放平台

### 1. 选择理由



* 国内项目首选，中文文档完善，坐标系与国内地理数据一致；

* 能力覆盖本项目全部需求：


  * JS API：底图展示、Marker、折线、行政区边界绘制；

  * Web 服务：地理编码、行政区查询、路径规划（驾车 / 步行通勤时长）、周边搜索；

* 个人开发者可免费注册，课程演示的调用量在免费额度内。

### 2. 使用方式



* 前端通过 JS API 渲染底图与点位；

* 涉及 Key 安全的服务端调用走后端代理，符合 SRS 中 NFR-SEC-03 的要求；

* 自定义底图样式，按风格规范降低底图饱和度、隐藏无关 POI。
