# 0003. 中期先用自制模拟地图，后期接入高德 JS API

- 状态：已采纳
- 日期：2026-09-28（决策）/ 2026-11-12（入库记录）
- 决策人：刘克、刘昊

## 背景

产品核心交互依赖地图：点位落图、缩放拖拽、详情联动。高德 JS API 需要 Web 端 Key、配额与域名白名单，Key 申请有审核周期；若中期版本等 Key，前端交互与联调会被整体阻塞。另一方面，答辩需要展示真实的城市点位，纯占位图无法验证「顺路」效果。

## 决策

中期版本用自研「模拟地图」组件代替底图：按经纬度线性投影到画布，绘制简化的道路与水域底纹，点位按真实坐标落在画布上；地图交互（缩放、拖拽、选点联动）由组件自身实现。接入高德时只替换地图渲染层，业务组件不动。

## 理由

1. 去掉外部 Key 依赖，组内任何人克隆即可运行，评审也能直接复现。
2. 投影公式与真实地图一致（经纬度 → 像素），后续替换时点位不会错位。
3. 模拟地图不消耗配额，调试频繁刷新不受限制。

## 备选方案

| 方案 | 优点 | 缺点 | 为何未采用 |
| --- | --- | --- | --- |
| 直接用高德 JS API | 真实底图，演示效果好 | 依赖 Key 与网络，配额受限，白名单配置易出错 | 中期进度风险过高 |
| 静态截图当底图 | 实现最快 | 无法缩放拖拽，点位与底图对不上 | 交互能力无法验收 |
| Leaflet + OpenStreetMap | 免费无需 Key | 国内访问速度不稳定，样式与设计规范不符 | 演示现场网络风险 |

## 后果

- 必须在架构说明与答辩中如实说明「中期为模拟地图」，不能把模拟地图当作真实地图演示。
- 接入高德时需要新增 Key 配置项（`AMAP_KEY`），且 Key 只能由后端下发或在构建时注入，不得硬编码进仓库。
- 模拟地图组件保留在仓库中，作为无网络环境下的降级方案。
