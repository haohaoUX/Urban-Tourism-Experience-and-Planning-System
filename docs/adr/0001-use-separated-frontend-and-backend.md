# 0001. 采用前后端分离架构（Vue 3 + FastAPI）

- 状态：已采纳
- 日期：2026-09-20（决策）/ 2026-11-12（入库记录）
- 决策人：刘昊、肖睿、刘克

## 背景

项目需要在 16 周内完成一个可演示的城市旅游路线规划工具，团队 4 人，前端与后端可并行开发。待办能力包括：地图渲染与交互、点位筛选、路线生成算法、路线增删改查。团队对 Python 更熟悉，希望算法部分（距离计算、排序）能在后端集中实现并可单元测试。

## 决策

采用前后端分离：表现层使用 Vue 3 + Vite 5，业务与数据层使用 Python + FastAPI + SQLAlchemy，通过 HTTP + JSON 通信，开发期由 Vite 代理 `/api` 到后端。

## 理由

1. 前后端职责边界清晰，两人可以同时开工，冲突面小。
2. FastAPI 自带 Pydantic 校验与 OpenAPI 文档（`/docs`），接口契约可以直接作为联调依据。
3. 路线算法放在后端，可用 pytest 直接单测，不必为前端搭一套测试脚手架。
4. 均为免费、社区成熟的框架，组员上手成本低。

## 备选方案

| 方案 | 优点 | 缺点 | 为何未采用 |
| --- | --- | --- | --- |
| 服务端渲染（Flask + Jinja） | 部署简单，单一进程 | 地图交互重度依赖前端 JS，模板拼接体验差 | 交互复杂度高，SSR 优势不明显 |
| 纯前端 + 本地存储 | 无需后端 | 路线数据无法跨设备共享，算法无法单测 | 课程要求体现后端分层与接口设计 |
| Next.js 全栈 | 一体化开发 | 需要 Node 运行时，团队不熟 | 学习成本高于收益 |

## 后果

- 交付时需要分别启动前端与后端，README 必须写明两段启动步骤与端口。
- 需要处理开发期跨域：已在 `vite.config.js` 中把 `/api` 代理到 `http://127.0.0.1:8000`。
- 若后续引入账号体系，鉴权应在后端统一实现，前端只保存 token。
